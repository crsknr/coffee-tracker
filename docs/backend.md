# Backend

The backend is a single Google Apps Script ([`backend/backend.gs`](../backend/backend.gs)) deployed as a web app on top of a Google Sheet. The sheet is the database; you can open it and edit anything by hand.

Base URL: `https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec`

## Setup

1. Create a Google Sheet and open **Extensions → Apps Script**.
2. Paste the contents of `backend/backend.gs` and save.
3. Run `initializeSheets()` to create the five tabs. Run `addSampleData()` too if you want some test data.
4. Fill in the **Config** tab (see below). For Telegram notifications, create a bot with [@BotFather](https://t.me/BotFather) and add its token and your chat ID.
5. Run `createDailyTrigger()` once to schedule the daily inventory report.
6. **Deploy → New deployment → Web app**, execute as *Me*, access *Anyone*. Copy the URL.
7. Paste the URL into [`backend/test-api.sh`](../backend/test-api.sh) and run it (needs `jq`), then put the URL in the firmware's `config.h`.

After you change the script, deploy a new version. Otherwise the URL keeps serving the old code.

## Sheets

### Transactions

Every action is one row. This is the source of truth; the balances and stock levels in the other tabs are kept in sync with it.

| Column             | Description                                                                      |
| ------------------ | -------------------------------------------------------------------------------- |
| Timestamp          | When the transaction was recorded                                                |
| User               | Username                                                                         |
| Type               | `consume`, `purchase`, `settle` or `undo`                                        |
| Item               | Comma-separated items, e.g. `Double,Oat Milk Portion`. `PayPal` for settle       |
| Quantity           | Comma-separated quantities matching the items. Negated for undo                  |
| Amount (€)         | Effect on the user's balance: negative for consume, positive for purchase/settle |
| Transaction ID     | Generated by the ESP32 (`esp32-<millis>-<hex>`), used for de-duplication         |
| Ref Transaction ID | For `undo` rows only: the ID of the transaction being reversed                   |

```
2025-01-11 08:34 | Christoph | purchase | Beans,Oat Milk Carton   | 2,6   | +75.30 | esp32-170490-a4f2 |
2025-01-10 11:01 | Christoph | consume  | Single,Oat Milk Portion | 1,1   | -0.50  | esp32-170492-c2d5 |
2025-01-09 17:44 | Bob       | settle   | PayPal                  | 1     | +17.00 | esp32-170493-d1f6 |
2025-01-09 17:50 | Bob       | undo     | PayPal                  | -1    | -17.00 | esp32-170494-e2a7 | esp32-170493-d1f6
```

### Users

| Column      | Description                                   |
| ----------- | --------------------------------------------- |
| Name        | Unique username                               |
| Active      | Only active users are shown on the device     |
| Balance (€) | Running balance, updated on every transaction |

### Inventory

What gets bought and restocked.

| Column             | Description                                                              |
| ------------------ | ------------------------------------------------------------------------ |
| Item Name          | e.g. `Beans`, `Cow Milk Carton`                                          |
| Unit Size (kg/L)   | Size of one unit                                                         |
| Cost per Unit (€)  | What one unit costs. A purchase credits the buyer with `quantity × cost` |
| Critical Threshold | Below this, stock is **red** and the device shows "Low on Beans!"        |
| Low Threshold      | Below this, stock is **yellow** and appears in the daily Telegram report |
| Stock (units)      | Current stock, can be fractional                                         |

### Products

What people consume.

| Column               | Description                                                      |
| -------------------- | ---------------------------------------------------------------- |
| Item Name            | e.g. `Single`, `Double`, `Oat Milk Portion`                      |
| Recipe               | Ingredients taken from inventory, e.g. `Beans:0.016,Water:0.060` |
| Calculated Price (€) | Raw cost from recipe × unit costs (for reference)                |
| Price (€)            | What is actually charged (you can add a markup here)             |

### Config

| Key                  | Example              | Description                                            |
| -------------------- | -------------------- | ------------------------------------------------------ |
| `treasurer`          | `Christoph`          | Buys stock and receives PayPal payments                |
| `paypal_link`        | `paypal.me/yourname` | Used to build the settlement QR code                   |
| `balance_threshold`  | `-10.00`             | Below this balance, the device asks the user to settle |
| `telegram_bot_token` | `123456:ABC-DEF…`    | Optional                                               |
| `telegram_chat_id`   | `987654321`          | Optional                                               |
| `daily_report_hour`  | `8`                  | Hour (0–23) for the daily inventory report             |

## GET endpoints

All responses are JSON with `"status": "success"` or `"status": "error"`.

### `?action=getConfig`

Everything the device needs at boot.

```json
{
  "status": "success",
  "users": [
    {"name": "Christoph", "balance": -15.40, "isTreasurer": true},
    {"name": "Laura", "balance": -3.20, "isTreasurer": false}
  ],
  "products": [
    {"name": "Single", "price": "0.40€"},
    {"name": "Double", "price": "0.60€"}
  ],
  "inventory": [
    {"item": "Beans", "price": "30€ / 1kg", "stock": "1.350kg", "status": "red"},
    {"item": "Water", "price": "0.85€ / 2L", "stock": "4.670L", "status": "green"}
  ],
  "config": {
    "treasurer": "Christoph",
    "paypalLink": "paypal.me/yourname",
    "balanceThreshold": -10.00,
    "criticalInventoryItem": "Low on Beans!"
  }
}
```

Users are active users sorted by name. `criticalInventoryItem` is the subtitle shown on the user page. It is empty when nothing is red; otherwise it names the item that is furthest below its critical threshold.

### `?action=getUsers`

Returns `users` and `criticalInventoryItem` in the same format as `getConfig`.

### `?action=getInventory`

Returns `inventory` in the same format as `getConfig`.

### `?action=getLastTransactions&user=<name>&limit=<n>`

The user's history, newest first, as rows ready to display. Multi-item transactions are split into one row per item. Only the first row of each transaction has `timestamp`, `action` and `amount`.

```json
{
  "status": "success",
  "transactions": [
    {"timestamp": "11.01 | 08:34", "action": "Purchase", "item": "Beans", "qty": "2", "amount": "+75.30"},
    {"timestamp": "", "action": "", "item": "Oat Milk", "qty": "6", "amount": ""},
    {"timestamp": "10.01 | 11:01", "action": "Consume", "item": "Single", "qty": "1", "amount": "-0.50"}
  ]
}
```

## POST endpoint

Every write goes to `POST <BASE_URL>` with a JSON body. The `type` field selects the operation. Every request needs `user`, `type` and a unique `transactionId`. The response always contains the user's new `balance` and the current `criticalInventoryItem`:

```json
{"status": "success", "balance": -16.40, "criticalInventoryItem": "Low on Beans!"}
```

Apps Script answers a POST with a 302 redirect, and the JSON is only returned at the redirect target. The firmware and `test-api.sh` both follow the redirect.

**consume**: charges the user each product's price and takes the recipe ingredients out of inventory.

```json
{"user": "Christoph", "type": "consume", "items": ["Double", "Oat Milk Portion"], "quantities": [1, 2], "transactionId": "esp32-1704900000-a4f2"}
```

**purchase**: adds the units to stock and credits the user with `quantity × Cost per Unit`.

```json
{"user": "Christoph", "type": "purchase", "items": ["Beans", "Oat Milk Carton"], "quantities": [2, 6], "transactionId": "esp32-1704900003-c5d6"}
```

**settle**: records a PayPal payment of `amount` (the user's full outstanding balance). The amount is credited to the user and deducted from the treasurer, and a Telegram message is sent.

```json
{"user": "Bob", "type": "settle", "amount": 17.00, "transactionId": "esp32-1704900005-f1a2"}
```

**undo**: reverses the user's most recent transaction. It writes a mirror row with negated quantities and the opposite amount, puts stock back, and for a settlement also reverses the treasurer's balance and notifies Telegram. You can't undo an undo.

```json
{"user": "Christoph", "type": "undo", "transactionId": "esp32-1704900006-b3c4"}
```

### Duplicates and errors

If the `transactionId` already exists, nothing is written. The response has `"status": "duplicate"` plus the current balance, so the device can safely retry or replay its offline log.

Errors look like `{"status": "error", "error": "<message>"}`. Possible messages: `Missing field: <field>`, `Unknown user: <name>`, `Unknown item: <name>`, `Unknown inventory item: <name>`, `Items and quantities length mismatch`, `Nothing to undo`, `Last transaction is already an undo`.

## Telegram

Notifications are skipped when the bot token or chat ID is empty.

- On settle: `💰 Bob settled €17.00 — check PayPal`
- On undoing a settle: `↩️ Bob undid settlement of €17.00`
- Daily at `daily_report_hour`, only when something is low:

```text
☕ Daily Inventory Report

🔴 Beans: 450g (critical — below 500g)
⚠️ Oat Milk: 2100ml (low — below 3000ml)
```
